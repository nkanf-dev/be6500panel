# 完整路由器管理版本

## 目标
一次性交付常用网络、无线、设备策略、服务及维护功能，不按独立模块向用户逐轮交付。性能和稳定性优先。保留原厂内核、无线、交换、加速和服务组件，Rust 负责认证、类型校验、操作编排和公开状态。

## 功能范围
- 网络：WAN/LAN、DHCP、静态绑定、IPv6、DNS、端口角色、双 WAN、VLAN/IPTV。
- 无线：SSID/加密/信道、MLO、TWT、访客网络、IoT、Mesh。
- 策略与服务：转发、DMZ、UPnP、DDNS、设备访问、QoS/限速及原厂支持的安全功能。
- 维护：时间/LED、计划重启、备份恢复、版本/升级状态、受控官方固件维护任务。

## 实现边界
- 现有 Rust 单监听、认证和串行写入通道不变；没有新增常驻代理、采集器或每客户端线程。
- 固定原厂 helper 调用通过有类型、白名单操作执行。客户端不能提供命令、脚本、文件路径或任意函数名。凭据仅保留在私有配置，公开响应只显示是否已配置。
- 原生读取按页面需要执行并使用短期公开快照；不把每个新模块都接入每秒采集。
- 原厂已实现的操作使用其生命周期，不将 MLO、端口映射、QoS、Mesh 降级为单个 UCI 字段。
- 编辑并保存功能支持不等于默认启用。保持当前接管关闭、已有配置和服务开关；设备更改只在明确操作时发生。
- 常规功能用一次保存，高风险连接或维护操作一次明确确认。共享恢复数据和日志有大小界限，不堆叠另一套防御框架。
- 官方固件功能按当前设备能力显示；无法作用于该型号的 USB/Docker 等不伪造可用。FRPC 和代理仍由当前受管核心提供。

## 验收
每一功能具备真实读取、类型化编辑、校验、执行、读回、合理恢复路径。源测试使用合成数据；真实设备验证公开状态和实际可恢复操作，不随意改变家庭网络。完整构建、前端及浏览器验证串行执行。以实际可见告警和操作结果验收。测量管理器资源、配置读取延迟和启用功能后的转发影响，不能以菜单数或 HTTP200 代替功能完成。

## 维护与验收边界
- 官方升级使用原厂 `upgradeRom` 的固定官方下载流程。原厂检查下载哈希、镜像和安全启动条件后执行刷写，不接受浏览器提供下载 URL、任意文件路径或自定义刷机命令。
- 地址变更由现有单监听管理器切换到已核对的 LAN 地址。页面重新登录后从公开任务记录恢复显式连接确认。
- 普通配置失败按实际配置与消费者恢复；固件刷写和恢复出厂不能通过 UCI 快照撤销。明确未启动的拒绝或下载失败与响应丢失分别处理。
- 真机验证可恢复操作与读回。重启、恢复出厂、刷写、家庭 WAN/LAN/无线切换的破坏性效果不作为已实际执行的验收结果。
