# Gateway scope and clear main screen implementation plan

**Goal:** Make normal use one gateway enable/disable action for declared observed LAN segments. New devices in those segments follow the configured rules automatically. Device selection remains advanced diagnostics, not onboarding.

**Architecture:** Reuse the verified single main-core routed-TUN backend and existing controlled capture lifecycle. Add a canonical gateway prefix scope to the pure planner, accepted-config builder and saved desired intent. No RPC/guardian framework expansion. A new first-screen card reads actual node/core/capture state and calls the existing guarded capture API explicitly; mounting or saving a node does not enable capture.

**Safety:** Start with IPv4 main `br-lan` only. Gateway segments come from fresh actual router LAN observations, not arbitrary browser prefixes or device inventory. A saved declaration must remain present in observed topology; missing scope suspends rather than broadens. Guest/IoT remain excluded. Preserve management/local/private/endpoint bypass, existing DNS authority, factory ACLs, independent SSH and positive-only fail-direct intent. Keep household capture disabled while implementing. Qualification uses a fixed synthetic /32 prefix canary through the same planner with no household devices.

## Shared types

`proxy.CaptureScope`: `CaptureScopeDevices = "devices"`, `CaptureScopeGateway = "gateway"`. Empty scope retains exact-device diagnostic/old-journal meaning only. `RulesPlanInput.Scope` and `RulesOwnership.Scope` plus `LANIPv4Prefixes []string` are optional/omitempty. Gateway input forbids client literal/list/MAC fields and requires 1..8 canonical disjoint RFC1918 IPv4 prefixes, /8..32, exact safe LAN interface and routed-TUN/IPv6Direct/FailureDirect. Production gateway API only accepts `scope:"gateway"` and `ipv6:"direct"`; trusted owner fills current observed LAN prefixes, never browser-provided prefixes.

`capture.Desired.Scope` and `LANIPv4Prefixes` persist an explicitly approved gateway declaration. `Status.Scope`, `LANIPv4Prefixes`, `InstalledLANIPv4Prefixes` distinguish current declared vs actual installed scope; Clients stays empty for gateway, never pretends inventory equals traffic coverage. Canonical clones protect observed/persisted arrays. Recovered journal recompile must validate exact gateway ownership/cleanup and keep old exact cleanup readable.

## Workstreams

1. **Pure planner:** reuse common routed-TUN chain construction; prefix source hooks and prefix rules, no MAC for gateway. Bound return to the installed prefixes and original LAN interface, exclude management destinations from return acceptance. Existing DNS REDIRECT ordering and bypasses remain. MARK entry hooks last; cleanup removes them first. No interface creation/deletion, global routes, firewall flush, offload or conntrack changes. Fake tests prove new device within declaration matches and outside/guest does not, disjoint validation, /32 canary and exact inverse cleanup.
2. **Saved intent + accepted builder/observation:** validate desired declaration; gateway builder checks fresh actual `br-lan` prefixes and accepted actual TUN/DNS/endpoint settings, no device enumeration authorization. Selects trusted observed main LAN prefixes only, keeps current management and own-TUN provenance validation. Recovery includes prefix fields. GET remains read-only, finite, stale-observation safe. Tests saved/recovered scope, missing topology, array clone and prefix route observation.
3. **API/root:** POST gateway no browser segments; obtain fresh capture observation, fill normalized main LAN prefixes before guarded Select. Device diagnostic POST keeps explicit selections. GET projects scope and installed ranges. Root adds /32 canary to existing isolated functional harness and repeats HTTPS/STUN/DNS/direct acceptance before any household activation.
4. **First-screen UI:** compact `网关路由代理` status card before node list, actual current node, actual configured rule mode and exact declared/installed network ranges. One `开启网关代理` / `关闭` action; show only actionable missing setup/error states, no technology choice/compatibility/disclaimer banners and no invented health/hit ratios. If configured core stopped, normal action starts it then enables gateway; no node/no binary redirects to setup. Existing node picker opens on explicit “更换节点”, subscriptions/ports/runtime internals advanced. Device diagnostics remain separate advanced tab. No writes on mount.

## Acceptance

Native tests/race/vet/ARM plus frontend typecheck/serialized full tests/build. Isolated prefix /32 test uses installed main TUN, same production planner, actual HTTPS204, STUN nonce/original source, ordinary DNS REDIRECT and direct/proxy results; withdraw exact owned rules and confirm main/node unchanged. Full /24 household activation is not implied by /32 acceptance and remains off until household fail-direct return and scope checks are qualified. No reboot/kernel/global offload changes or new service framework.
