# Native owner assembly and explicit startup

NativeOwner::open assembles the existing exclusive Manager, native capture/readiness hooks, HTTPS source, fixed private artifact directories and saved intent. It creates no core/checker/download/network cleanup. Trusted ip/iptables bindings are supplied by startup, never HTTP. Existing files and emergency reserve are preserved. No boot PID or arbitrary executable is adopted; initial artifacts are None and verified acquisition creates executable trust.

Data/run roots and fixed children require absolute no-follow components, same-user private0700 and physically separate storage. Public/symlink/overlapping roots refuse without mode repair. The services/.manager.lock is held before explicit startup network actions. Duplicate owner refuses without executing cleanup or core actions.

initialize explicitly withdraws validated capture cleanup before saved-on service reconstruction. Failed cleanup retains the same owner/journal/executor for retry; mutation API remains startup_cleanup_pending, while authenticated GET/DELETE/off remain possible. Completion during cancellation does not clear the startup gate. Successful withdrawal is remembered and is not replayed; valid cancellation-cleared retry can continue. Initial saved restore dispatch runs once, including per-service failures; existing bounded poll_recovery owns later retries and initialize cannot reset its eight-attempt/backoff budget.

The borrowed runtime API uses one existing owner. close attempts capture withdrawal and Manager close, retains failures and cancels later initialization. Repeated close is idempotent only after actual cleanup. Manager store lock remains held through owner lifetime; fixtures explicitly drop closed owners before re-opening rather than weakening production locking. No Drop stop bypass, artifact scavenger, new daemon or observer/download worker.

Fresh capture LAN/config observations and native readiness share the same cancellation flag. Source acquisition retains its own existing absolute cooperative deadline. This component is not a hard realtime shutdown promise and cannot interrupt an uncooperative OS syscall. FRPC readiness is retained process liveness only, not tunnel connectivity.

Qualification uses private temporary files, fake network command programs and fake FRPC core; source HTTP is explicit numeric-loopback fixture policy. Tests cover constructor zero actions, duplicate lock, cleanup-before-fetch, failure/retry and API startup blocking, cancellation before/after withdrawal, repeated initialization, malformed saved intent, root protection, close without Run and actual acquired FRPC close/rebuild. Two scoped review findings received red/green regressions: cancellation gate and repeat restore-dispatch refetch. Eight integration cases plus private cancellation unit and strict Clippy pass before complete gate. Full host/ARM evidence is external rust-native-owner-startup-*; final results remain pending until observed.

Main and bootstrap remain unchanged in this slice. Production management migration, real Linux ARMv7 lifecycle/kernel execution, legacy desired/journal withdrawal, full UCI/device/history/telemetry/maintenance parity, remote tunnel/TLS termination and target RSS/latency gains are not claimed. No real router/core/capture action was executed.
